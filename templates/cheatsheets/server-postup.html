Server PostUp / PostDown

Common lifecycle commands for firewall and NAT behavior when the server interface starts or stops.

Basic NAT gateway

VPN clients can reach networks through the server's main network interface, and replies are masqueraded back through the server.

Example:

PostUp = iptables -A FORWARD -i %i -j ACCEPT
PostUp = iptables -A FORWARD -o %i -j ACCEPT
PostUp = iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i %i -j ACCEPT
PostDown = iptables -D FORWARD -o %i -j ACCEPT
PostDown = iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE
LAN access only

VPN clients can reach a LAN through the server, but this does not intentionally turn the VPN into an internet gateway.

Example:

PostUp = iptables -A FORWARD -i %i -o eth0 -d 192.168.50.0/24 -j ACCEPT
PostDown = iptables -D FORWARD -i %i -o eth0 -d 192.168.50.0/24 -j ACCEPT
Block one destination LAN

VPN clients are prevented from reaching a sensitive LAN.

Example:

PostUp = iptables -A FORWARD -i %i -d 192.168.99.0/24 -j DROP
PostDown = iptables -D FORWARD -i %i -d 192.168.99.0/24 -j DROP
No custom rules

The tunnel comes up without adding firewall or NAT rules. Use this when routing and firewalling are handled elsewhere.

Example:

leave blank

Replace eth0 with the server's real outbound interface.

More details: wg-quick man page
